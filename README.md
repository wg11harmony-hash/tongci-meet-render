# 同词相遇 · Render 版

支持 2–4 人的联机网页小游戏。创建时选好人数，各自输入词语，全员确认后同时揭晓；同词玩家自动合队，队内共享填写并随机选出团队答案，直到全场答案一致。朋友使用浏览器即可加入，无需 ChatGPT 账号。

**部署操作见 [Render 部署指南](./Render部署指南.md)。**

也可使用 [Replit 部署指南](./Replit部署指南.md)，仓库已附带 `.replit` 启动和构建配置。

## 项目组成

- `src/App.tsx`：游戏界面，沿用紫色与薄荷绿设计。
- `src/styles.css`：响应式样式。
- `lib/game.mjs`：同词规则和房间状态处理。
- `server/app.mjs`：普通 Node.js HTTP 服务，同时提供网页和联机接口。
- `server/index.mjs`：启动入口，读取 Render 提供的 `PORT`，监听 `0.0.0.0`。
- `render.yaml`：Render Free Web Service 配置，已声明免费计划。
- `package-lock.json`：锁定依赖，供 `npm ci` 使用。
- `dist/`：交付压缩包内附带的已构建网页，可直接本地运行；Render 构建时会重新生成。

此版本使用 React + Vite 构建页面，运行后台只用 Node.js 内置模块。网页与接口共用一个地址；不依赖 Cloudflare D1、Sites 账号或 OpenAI 密钥。

## 本地试玩

需要 Node.js 24。压缩包已包含 `dist/` 时，解压后直接运行：

```sh
node server/index.mjs
```

打开 `http://localhost:3000`。用 2–4 个独立浏览器标签页模拟玩家：一人创建房间并选择 2、3 或 4 人，其他人打开邀请链接加入，人数到齐自动开始。每个标签页保存独立座位凭证。

## 修改和构建

```sh
npm ci --include=dev
npm run build
npm test
npm start
```

开发时可分别开两个终端：一个运行 `npm start`，另一个运行 `npm run dev`。Vite 会把 `/api` 请求转发给 `http://127.0.0.1:3000`。

## 联机规则

- 创建房间时选择 2、3 或 4 人，人数到齐自动开始，本局人数固定。
- 开局每人独立作答。每人确认后不能修改，全场确认后统一揭晓。
- 同一轮最终答案相同的玩家或队伍自动合并，三人同词会直接合成三人队；队伍本局不拆分。
- 合队后队友实时看到彼此正在填写的内容及确认状态。填写内容短暂防抖后发送，其他浏览器通过轮询同步，通常约一秒内可见。
- 队内所有成员确认后，由服务端使用 `crypto.randomInt` 等概率抽取一位成员的答案作为团队答案。独立玩家直接使用自己的答案。重复请求不会重新抽取。
- 其他队伍在全场确认前收不到本队填写内容或团队答案；全场揭晓后只公开团队最终答案。
- 只比较当轮个人／团队最终答案，相同就继续合并，全场答案一致即游戏结束。
- 去掉首尾空格后逐字比较；不做同义词或 AI 判断。
- 全员准备后进入下一轮；结束后全员准备可重新开始，新一局恢复所有人独立作答。
- 座位凭证自动保存在当前浏览器标签页中；同一标签页刷新后可恢复。
- 已同步的未确认填写内容可在刷新后恢复；确认后的答案锁定。网络延迟时旧填写请求不会覆盖新内容，过期轮次请求会被拒绝。
- 多人结果可导出 PNG 长图，包含每轮队伍成员、最终答案及被抽中的成员。

## 免费版的数据行为

房间存在单个服务进程的内存里，最长有效 24 小时。服务重启、重新部署或休眠后，旧房间可能被清空，需要重新开房。结果长图可保存到自己的设备。

这适合 2–4 位朋友临时玩几局。如果以后需要长期战绩、多个服务实例或永久保留房间，再接入独立持久化数据库。

## 环境变量

| 名称 | 含义 | 默认值 |
| --- | --- | --- |
| `PORT` | 服务端口；Render 自动提供 | `3000` |
| `HOST` | 监听地址 | `0.0.0.0` |
| `NODE_VERSION` | Render 的 Node.js 版本 | 配置中为 `24.22.1` |

`GET /healthz` 是公开健康检查接口，正常返回 `{"ok":true}`。

本地验证通过不等于已在你的 Render 账号上线。上线后需用你和朋友各自的网络打开实际分配的网址，完成一次多人试玩。
